# Security Policy

HarnessLab coordinates models, tools, credentials, temporary workers, and potentially untrusted content. Security reports must not be posted in public issues.

## Reporting a vulnerability

Use GitHub private vulnerability reporting when it is enabled for this repository. Include the affected component, reproducible steps, impact, and any safe proof of concept. Do not include real credentials, personal data, or production data.

## Security boundaries

The project will treat the following as approval-gated or prohibited by default:

- destructive or irreversible operations;
- production deployment and infrastructure changes;
- access to production secrets or user data;
- financial transactions or paid-service authorization;
- repository administration, branch-rule changes, and direct pushes to `main`;
- disabling audit, evaluation, authentication, or policy controls.

## Supported versions

No production version is supported yet. Security guidance will be updated before the first public release.
